# Agent Room v2: Agentverse

Plan for turning the user's "Agentverse" brief (2026-11-18) into the app, written
after the first 3D workspace shipped (PLAN.md M17). PLAN.md stays the record of
decisions and history; this file is the v2 roadmap. Each phase ends in a check.

## 1. Goal and the hard constraint

Goal: when you open the app you see a small space-station HQ already alive. You give
Claude a task and watch the agents organise themselves, visit stations, delegate,
hand over results, all driven by what Claude Code really does.

Hard constraint (the user's): the app stays usable as an always-on companion. It must
not draw much power. Budget, measured with the release build on the user's M2:

| State | CPU (one core) | Memory |
|---|---|---|
| No Claude activity (any view) | ~0 % (sleeps) | ≤ 250 MB |
| Claude working, window unfocused | ≤ 10 % | ≤ 250 MB |
| Claude working, window focused | ≤ 25 % | ≤ 300 MB |

Baseline today (measured 2026-11-18, release build, 3D view, unfocused): 19 % CPU and
212 MB with **no** activity, 20-33 % during a replay. 2D idles at about 0 %. The 3D view
never sleeps because the robots' idle animation keeps it redrawing. Fixing that is
phase 0, before any new feature.

## 2. Engine decision: stay on Bevy (not React Three Fiber)

The brief asks for React Three Fiber and Three.js. We stay on Rust and Bevy:

- **Power.** R3F needs a browser engine: Electron (a Chromium per app, typically
  300+ MB) or Tauri (the system WebView, lighter). A WebGL page also lacks the fine
  control we already use: sleep until an event arrives, 10 fps when unfocused, render
  only on change. Bevy gives us a native Metal app with that control today.
- **It already works.** Hooks, permission answers, the channel, mini mode, the 3D HQ
  with Blender-made robots, stations and environment, bloom, activity holograms,
  light trails and the HUD are all built and checked in Bevy.
- **The brief's real requirement is architectural**, and it holds in Bevy: the
  backend says what happened, the front end decides how to show it (section 4).

What R3F would give: drei helpers, a big ecosystem of effects, and HTML/CSS panels that
are quicker to style than egui. If panel polish in egui becomes the bottleneck, the
fallback is to keep Bevy for the world and render panels in a WebView overlay, not to
move the whole app. Revisit only with a measured prototype (same scene, same budget).

## 3. What the data can honestly show

Rule from the brief: never fabricate activity. What Claude Code gives us:

| Brief asks for | Source | Status |
|---|---|---|
| Read / write / run / search / web | `PreToolUse` / `PostToolUse` tool name and input | have |
| Subagent spawned, done, its task and report | `SubagentStart` / `SubagentStop`, `Agent` tool input | have |
| Delegation and handover | `Agent` tool call (parent → child), `SubagentStop` | have |
| Waiting for input | `PermissionRequest`, `Notification`, `AskUserQuestion` | have |
| Errors | `PostToolUseFailure`, `StopFailure` | have, not shown yet |
| Current task | the user's prompt (`UserPromptSubmit`) | have |
| Tokens, cost, latency per step | transcript JSONL (`message.usage`, tool `durationMs`) | readable, not wired |
| Messages between agents | `Agent` input (task) and the sub-agent's final report | have (two per child) |
| Task dependencies, % progress | nothing | **not available**: show steps done / running, never a made-up % |
| Agent "thoughts" | nothing (hidden) | abstract "thinking" visual only, no fake text |

## 4. Architecture

```
hooks ──► room-hook ──► socket ──► RoomEvent (room-proto)
                                      │
                                      ▼
                         Model (sessions, agents, poses)   ◄── one source of truth
                                      │ Change
                     ┌────────────────┼──────────────────┐
                     ▼                ▼                  ▼
               2D scene          Director (3D)       History (new)
            (mini, fallback)   stations, routing,   ring buffer of events
                               capsules, holograms   + time, for replay
                                      │
                                      ▼
                       3D layers: environment │ stations │ agents
                                      │
                                    HUD panels (egui)
```

- **Model** stays the only state. The 3D view stops following 2D entities: a
  **Director** turns `Change`s into per-robot intents (go to station, hand over,
  wait, error) and plays them. This removes the 2D scene as a hidden dependency of
  the 3D one (today `view3d` reads 2D `Agent` entities and the `Roster`).
- **Intent per robot, newest wins.** Events can arrive faster than a robot walks.
  Each robot keeps only its newest intent, so it never replays stale steps, and short
  tool calls (under ~1.5 s) update the hologram without a walk, like `MIN_DWELL` in 2D.
- **History** records every `RoomEvent` with its time, in memory and in
  `~/.agent-room/history/<session>.jsonl`. Replay feeds the same pipeline from that
  file at a chosen speed, so live and replay cannot drift apart.
- **Layers stay separate files** (already true): `environment/*.glb`,
  `stations/*.glb`, `robot/robot.glb`, each with its Blender script in `tools/blender/`.

## 5. Phases

Each phase lists its features, its check, and a resource note.

### Phase 0: sleep when nothing happens (power first)

- 3D redraws only while something changes: walking, a hologram growing, a capsule
  flying, a permission countdown. Idle robots hold their idle pose; the idle clip
  plays only while the window is focused.
- Pulse effects (rings, orbs, documents) stop when unfocused.
- Build the lever: `scripts/measure.sh` runs the release build, replays the spike
  log, samples `top`, and prints idle and active CPU and memory. Every later phase
  reruns it.

Check: `scripts/measure.sh` meets the budget table (idle 3D about 0 %, active
unfocused at most 10 %).

### Phase 1: the Director and a truthful event map

- `director.rs`: `Change` → robot intents. The tool-to-station map lives in one
  table: Read/Grep/Glob → reading station, Edit/Write → writing desk, Bash/MCP → lab,
  WebSearch/WebFetch → research station, `Agent` → delegate, `SubagentStop` →
  handover, permission/question → waiting, failure → error.
- Robots no longer read 2D entities; avatars are keyed by agent id.
- Errors: a red ring and a warning icon over the robot until its next success.
- Tests feed a recorded event log and assert the intents (a pure function, no
  rendering).

Check: tests green; the spike replay looks as it does today; 2D unaffected.

### Phase 2: stations the brief adds

- Split "Bookshelf" into a **Reading station** (files) and a **Research station**
  (web: floating cards, a small knowledge-graph hologram).
- Handover: the user decided on 2026-11-17 to hand over at the main desk. Keep that,
  and give the main desk a small handover ring in front, so the brief's "space for two
  robots" exists without a separate trip.
- **Docking bays** for finished or idle sub-agents (the brief's resting areas),
  instead of vanishing at once.
- Blender: `stations.py` gains `research.glb` and `dock.glb`; the floor rings move.

Check: screenshots from the app camera with every station in view.

### Phase 3: spawning, delegation, handover, communication

- Spawn: a holographic materialisation (scale + emissive fade + a ring; no custom
  shader).
- Delegate: the main robot turns to the new one, and a task capsule flies over on a
  glowing arc with a few particles (a handful of instanced quads, no particle engine).
- Handover: the sub-agent walks back, and the capsule flies to the main robot.
- Communication line: parent ↔ child line while the child works, brighter while data
  moves.

Check: a replay with two sub-agents; screenshots at each beat.

### Phase 4: panels and the timeline

- Top bar (exists): add total spawned agents and a settings button.
- Right panel: agent list (name, role, current task, status, parent, runtime);
  clicking one highlights its robot (ring + camera focus).
- Bottom: a chronological event stream with icons; click an event for its details
  (tool input and result from the hook payload).
- Agent details (exists): add tool calls with input and output, parent and children,
  errors.
- Notifications: small toasts for spawned, completed, handover, failed, waiting.
- Minimap: a 2D egui overview drawn from station and robot positions (cheap; no
  second 3D camera).

Check: screenshots; every panel works with two sessions and with none.

### Phase 5: camera and time machine

- Orbit, pan and zoom (mouse and trackpad), reset, focus on and follow an agent.
- Cinematic mode: follows the latest meaningful event, at most one cut every few
  seconds.
- Time machine: pause, rewind, replay at 0.5× to 8× from History (section 4).

Check: a replay from the history file matches the live run in screenshots.

### Phase 6: operations room and polish

- Operations room (toggle): tokens, cost estimate, tool-call counts and durations,
  errors per agent, read from the session transcript (`transcript_path`).
- Atmosphere within budget: a few slow dust motes, holo flicker, window stars; all
  frozen when unfocused.
- Optional and measured: volumetric fog (built into `bevy_pbr`) and cheap
  reflections (an environment map), only if they fit the focused budget.

Check: `scripts/measure.sh` after each item; drop anything over budget.

## 6. Ideas that make it more fun to use

Picked from the brief and ranked by delight per cost:

1. **Follow cam on click** (phase 5, cheap): click a robot and the camera follows it.
2. **Time machine** (phase 5): rewind a finished turn and watch it again at 4×.
3. **Docking bays** (phase 2): finished sub-agents walk to a charger and power down
   instead of vanishing.
4. **Trophy shelf**: one glowing cube per finished turn of the day; click one to read
   that turn's final answer.
5. **Sound** (off by default): soft blips for spawn, handover and permission requests.
6. **Sessions as wings**: each live Claude session gets its own wing of the station
   (today: switch rooms from the HUD list).

## 7. Out of scope for now

- Task dependency graphs and % progress (no data; it would be invented).
- Screen-space reflections and heavy volumetrics by default (power budget).
- A web front end (section 2).

## 8. Open questions for the user

- When Claude is idle, should the 3D view freeze completely (phase 0's default) or
  keep a slow idle animation at a few fps?
- Sessions as wings (idea 6): worth a phase, or is the HUD switcher enough?
- Sound on or off by default?
